This page proves the whole point of an embeddable widget: it renders here, on a page the widget platform's own team never wrote, served from a completely different origin than the API.

Different origin, on purpose: serve this file with python -m http.server 5500 (or npx serve) from the customer-site/ folder -- so this page lives at http://localhost:5500 while the API lives at http://localhost:8000. That mismatch is exactly what makes CORS, the config endpoint's cache headers, and the submission endpoint's cross-origin handling actually get exercised, instead of just looking correct on paper.
